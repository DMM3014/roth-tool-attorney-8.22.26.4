# Roth IRA Conversion & Retirement Planner — PRD

## Original problem statement
> "turn this spreadsheet into a web based Roth IRA conversion and retirement planner keep the spreadsheet as the tax engine and preserve separation of ordinary income from ltgc and dividend income"

## Product goals
1. Faithfully reproduce the user's V17 Excel tax model (spreadsheet-grade parity, < 0.5% delta).
2. Preserve strict separation of ordinary income vs LTCG / qualified-dividend income at every step.
3. Provide interactive multi-year strategy optimization beyond what single-year Roth calculators offer.
4. Client-ready output for the user's advisory practice (analytics, PDF presentation).

## Architecture (as of 2026-07)
- **Backend**: FastAPI + Python + NumPy. Core files:
  - `projection.py` — spreadsheet-grade tax + projection engine (V17 alignment)
  - `strategy_optimizer.py` — multi-year sweep (start × stop × bracket, phased schedules)
  - `ss_optimizer.py` — Social Security claiming-age optimizer
  - `montecarlo.py` — v3.1 stochastic engine
  - `tax_engine.py` — single-year fill-the-bracket tools
  - `server.py` — FastAPI routes, rate limits, DoS caps
- **Frontend**: React + Tailwind + Recharts + Sonner (browser print for PDF).
- **DB**: MongoDB (scenarios only).
- **AI**: Google Gemini via `google-genai` SDK — default env key with BYOK fallback.
- **Tests**: 190 pytest cases, all passing.

## Notes for future agents (critical)
- **NEVER issue parallel search_replace calls against the SAME file** — they race and silently drop edits (bit 3 times in Phase 51 alone). One edit per file per batch, then grep-verify each landed.
- Mass pytest vs live URL trips the 5/min auth rate limit; conftest no longer attempts HTTP pin verify unless ADVISOR_PIN is set. If master login locks out: delete mongo `auth_config` doc `_id:"master_lockout"`.
- Estate/EP API contract: send ALL y2_* fields for projection mode; the frontend folds cash+real_estate into taxable at both deaths (sold-and-reinvested convention).
- Report page numbering: flowPages = selected plans + optional compare table + 2 (sensitivity + combined) when a compare scenario is chosen.
- **Client Report page spans (updated 2026-08-21)**: several sections print MULTIPLE pages — Income & Expenses ×3, Legacy ×4, Inputs Appendix ×2 — via a local `foot(i)` offset helper. `ClientReportBody.basePages` is **15** (Cover, Assumptions, Overview, Convert-or-Skip, Roth Conversions, Savings, Income&Expenses ×3, Cash Flow, Taxes, Monte Carlo, Legacy ×3) plus THREE conditional offsets: `L = 1` for the optional advisor cover letter, `O = 1` for the opt-in objectives page (both applied as `n + L + O` to every fixed page number after the cover), and 1 for the "Advisor & Technical Appendix" divider (`techPages > 0`). Optional pages (bracket snapshots, paired MC, regime, heir-rate sensitivity, basis, EP flowchart, appendix) each add to `totalPages`. Verify by counting `.pdf-page` nodes in `client-report-preview-inner` and reading the last footer.
- **Cross-surface shared preferences live in `/app/frontend/src/hooks/`** and all follow the same pattern (one localStorage key + a same-tab CustomEvent + a cross-tab `storage` listener): `useSharedGuardrail`, `useSharedHalt` (MC conversion-stop, default 20% / 1yr), `useFlowPlans` (which EP plans print — Client Report AND EP Flowchart tab), `useObjectivesPage` (objectives page on/off, default OFF). Add new shared advisor prefs here rather than duplicating useState in two components.
- **Editorial rule (advisor's standing instruction)**: the client-facing deck and report must NOT imply a winner or issue directives. No "Best…", "wins", "recommendation", "should", "commit to". Use "leads under <assumption>", "illustrated", "result under the average-market assumption", "Planning Considerations". Any assumption-dependent metric must carry its qualification IN THE LABEL, not only in a footnote. See CHANGELOG items 27–28.
- **Every comparative page needs a `HoldConstantBand`** ("Constant in both scenarios" / "Variable changed") and a paired "in today's $" column via `lib/pv.js`. See CHANGELOG items 31–32.
- **`mcScenarioSig` excludes `optimizer` AND `planning_objectives`** — four call sites must agree (Presentation, ClientReport, RegimeComparePanel, StrategyStressTest) or the deck falsely reports stress/regime results as stale. See CHANGELOG item 30.
- **First-death year must come from the household (`dob + life_expectancy`), never from a `filing_status` change** — the flip lands a year late and doesn't fire when the survivor files MFJ. `detectMilestones(rows, scenario)` and `EpFlowchart.deriveDeathYears` both do this. See CHANGELOG item 43.
- **At the first death the taxable accounts pool onto the SURVIVOR's account** (`_step_up_basis`), and new surplus sweeps to a living owner's account (`_living_owner_target`). IRA/Roth intentionally stay on their original owner's row. See CHANGELOG item 42.
- **Print height limit ≈ 1050px** per `.pdf-page` (nominal box 900px, A4 printable ≈ 277mm at 190mm width). Anything taller clips in the generated PDF. Measure with `height / (width / 720)` in the preview.
- **Beneficiary rate band**: `POST /api/legacy/heir-rate-sensitivity` re-prices ONLY the heirs' SECURE-10 horizon per candidate rate (the parents' projection is rate-independent). Never re-run the whole projection per rate.
- TWO ENVIRONMENTS: production runs a prior build until user redeploys — reviewer PDFs may reflect stale copy (e.g., the "do not include" italic issue). Before "fixing" copy an advisor quotes from a PDF, grep the repo — the string may already have been removed in a later build.
- **Client Deck tab (2026-08-21)**: `Planner.jsx` `value="client-deck"` renders `<Presentation curated />`. Which pages print is advisor-ticked via `lib/deckPages.js` + `hooks/useDeckPages.js` (localStorage `client_deck_pages_v1`) and the `DeckPagePicker` card; inside `PresentationReport` every page is gated by `show(k)` = `curated ? !!deckPages[k] : true`. To add a deck page: add a `DECK_PAGES` row, a `DECK_DEFAULTS` entry if it should be in the short deck, and wrap the page in `{show("<key>") && (<>…</>)}`. The FULL Presentation deck must stay unconditional.
- **Sequence-of-returns stress test**: `cfg["return_path"]` = `{start_year, equity_share, equity_returns[]}` is the ONLY way to make the engine deviate from flat growth; it shocks the equity sleeve of Taxable / Tax-Deferred / Tax-Free only. `backend/sequence_stress.py` builds the paths (mean-preserved variants must keep `∏(1+blended_t) = (1+r_ref)^N` — there is a test asserting a no-cashflow run lands on the same balance). Settings are shared through `hooks/useSeqParams.js`; the tab, the Client Report page and the deck page all read it.
- **Monte Carlo guardrail / halt live in shared stores** (`useSharedGuardrail`, `useSharedHalt`) used by the MC tab, the Client Report AND the Presentation/Client Deck (`presentation/McBehaviorCard.jsx`). Any new surface that shows these rules MUST use the hooks, never local state. The printed disclosure is `shared/McBehaviorNote.jsx`, which calls the hooks itself — drop it in a page, no props.
- **Convert-or-Don't-Convert copy is centralised** in `lib/convertSkipCopy.jsx` (`ConvertSkipNarrative`, `ConvertSkipFootnote`) and consumed by BOTH `clientReport/ConvertSkipPage.jsx` and `presentation/ConvertSkipDeckPage.jsx`. Edit the wording there once; don't fork it per surface.
- **`presentation_branding_v1` is a shared write-through store** (`hooks/usePresentationBranding.js`) — NEVER go back to plain `useState` + a Save button. The Presentation tab and Client Deck tab are two `<Presentation>` instances, so unsaved branding state diverges and picker rows silently revert on tab switch (found in iteration_86).
- **`estate_settlement_pct` default is 0** (advisor request 2026-08-21). It lives in THREE places and the per-advisor Mongo doc wins: `backend/defaults.py`, `backend/user_defaults.json`, and `advisor_defaults.<role>:<sub>.config`. Any future default change must touch all three or the UI won't move.
- **`_apply_spousal_rollover` retitles ONLY Tax-Deferred / Tax-Free.** Taxable + Real Estate are owned by `_step_up_basis` and the `merge_basis_at_first_death` flag; folding them into the survivor's account defeats merge=False (regression caught 2026-08-21).
- **Report date is never restored from localStorage** — all three `loadBranding()` helpers (clientReport, ssReport, Presentation) overwrite `presentation_date` with today after the spread. Don't "fix" this by removing the override.
- **`BasisTradeoffCaveat` (shared/PrintBlocks.jsx)** prints only when every plan's `metrics.forgone_step_up` < $1,000 — it exists so Plan 2 ≈ Plan 3 in a Roth-heavy scenario isn't read as a general rule.
- **EP flowchart print pages**: each selected plan prints TWO pages (`cr-page-flow-plan-N` diagram + `cr-page-flow-plan-N-detail` arithmetic), so `flowPages = flowSel.length * 2 + …`. Measured heights after the 2026-08-21 fit pass: 900–1034px (budget ≈ 1050). `PlanFlowchart` hides its in-card badge/title when `hideSubtitle` is passed.
